# AgentHub 运维手册

适用版本：v2.40.x。所有命令默认在 AgentHub 源码目录执行；`<root>` 指大脑根目录（如 `D:\agent资料\zcode项目记录`）。

## 0. 五分钟体检

```bash
python cli.py --root <root> doctor        # 全项巡检，逐条给修复建议；有问题退出码 1
```

等价 MCP：`hub_sentry(action="report")`（只出报告、不广播）；日常哨兵用 `hub_sentry()`（发现问题广播给所有 agent）。

体检项：环境 / 运行版本 / 数据库 / 备份 / 规则闸门 / 陈旧记忆 / 幽灵记录 / 重复记忆 / 记录四段式 / 日期格式 / 任务治理 / Inbox / 停滞项目。

## 1. 工具全部消失或客户端连不上

按顺序排查：

1. **进程是否活着**：`python cli.py status`；客户端里 MCP server 显示 failed/红点即未启动。
2. **stdout 污染**（最常见）：MCP stdio 下任何 `print` 都会让 JSON-RPC 解析失败，表现为工具全没了。检查进程加载模块里是否有控制台输出；`hub_ops_run(name="stdout_guard", target=<目录>)` 可扫描。
3. **配置路径**：每个 agent 的 MCP 配置应指向部署目录 `~/.agenthub/mcp_server/agenthub_mcp.py`（或源码 `agenthub_mcp.py`）。改完配置需重启客户端。
4. **版本/协议**：`python cli.py call hub_health` 能通说明服务端正常，问题在客户端握手；检查 `initialize` 是否返回 `protocolVersion`。
5. **限流**：单工具 600 次/60s、单 agent 2000 次/60s（环境变量可调，`AGENTHUB_RATE_LIMIT=off` 关闭）。被拦是业务错误 `isError`，不会断连。

## 2. 部署了但没生效（跑的是旧代码）

```bash
python cli.py deploy                              # 源码 → ~/.agenthub/mcp_server
```

`runtime_health` 会点名「进程加载的代码落后于磁盘」的文件。两条途径：

- 在 agent 会话里经 MCP 调用：`hub_ops_run(name="runtime_health")`、`hub_agent(action="status", agent="<名>")`；
- CLI / `doctor`：R24 起会读取运行中 MCP 进程落盘的**运行标记**（`~/.agenthub/runtime/serve-<pid>.json`，30s 心跳、120s 过期），据此给出「一致/需重启」并注明「观测来源：心跳中的 MCP 进程」。

CLI 自己仍不是在跑的服务进程（`python cli.py call …` 会导入模块但只活几秒）。**没有新鲜标记时**它诚实返回「无法判断」——这通常说明各 agent 的 MCP 进程还没重启到 v2.40.93+，不是故障。**重启各 agent 的 MCP 进程**后新代码才生效，标记也会随之出现；只 deploy 不重启等于没发。判定基准是进程加载时的指纹与启动时刻，心跳只刷新标记文件的 mtime，不会把旧代码洗成一致。标记按不可信输入校验：坏 JSON、空目录、不可解析或未来的启动时刻、非字典指纹都会被忽略（未来时刻曾可伪造「一致」），不会让体检崩溃或给出假结论。进程被强杀留下的旧标记会由下一次服务启动或超过 20×TTL 的清理逻辑移除。

`hub_agent(action="verify")` 的验证快照绑定的是**当前进程加载代码的源码指纹**（md5，不是 mtime），所以「部署了但没重启」会让快照当场标为过期——这是正确行为，不是误报。重启后再 verify 一次即可。快照同时记录**代码树**（源码目录 / 部署目录）：从另一棵树（例如 CLI 导入源码树）复查时显示「无法据此判断」，不会把另一棵树多出的文件误报成过期；在 agent 会话里重跑 verify 即绑定部署树。

## 3. 备份、校验与恢复

### 3.1 备份

```bash
python cli.py --root <root> call hub_export action=backup
```

产物：`<root>/_hub/backup/brain-YYYYMMDD-HHMMSS.zip`，内含：

- `brain.db`：用 sqlite 官方 backup API 取的一致性快照（含 WAL，**不是**文件复制）；打包前先跑 `PRAGMA quick_check`，不通过即放弃并清理临时文件
- `_AgentHub_备份清单.txt`：生成时间、跳过文件/目录数量与原因
- 其余为备份时刻的项目文件树：排除构建/缓存/依赖/备份目录（`build*`、`dist*`、`node_modules`、`.venv`、`backup` 等），单文件 >50MB 跳过（`AGENTHUB_BACKUP_MAX_FILE_MB` 可调，0=不设上限）

可靠性：先写同目录临时文件，成功后 `os.replace` 原子改名——中途失败不留半成品、也不会覆盖已有备份；同一秒内重复备份自动追加序号。

### 3.2 盘点与校验

```bash
python cli.py --root <root> call hub_export action=backups
python cli.py --root <root> call hub_export action=verify path=<zip 路径>
```

四类备份：`zip` 整包 / `legacy_db` 旧版仅库 / `snapshot` 在线快照（`_hub/brain-backups`，自动轮转）/ `manual_bak` 手工 `.bak`。

`verify` 会读取包内清单、对库快照跑 `quick_check`，并输出记录/记忆/项目/文件数与跳过统计；末行「完整性 ok」才算通过。

### 3.3 清理（默认只预演）

```bash
python cli.py --root <root> backup-prune              # 预演：只列候选，不删
python cli.py --root <root> backup-prune --apply      # 真删：保留各家族最新 N 份 + 7 天内不动
```

安全线：主库 `brain.db`、`-wal`、`-shm` 永不碰；只删四类备份模式命中的文件；删除写 journal 可追溯。首次建议先看预演结果。

### 3.4 恢复（手工，先停写）

1. **停掉所有 agent / GUI**，确认没有进程再写 `<root>/_hub/brain.db`。
2. 保留现场：把当前 `brain.db` 改名为 `brain.db.before-restore-YYYYMMDD`；把 `brain.db-wal`、`brain.db-shm` 移走（恢复后由 SQLite 重建）。
3. 解压备份到临时目录，取其中的 `brain.db` 放回 `<root>/_hub/brain.db`。
4. 项目文件按需恢复：zip 里的文件树是备份时刻状态，**整树覆盖会冲掉更新的工作**——只挑丢失的文件恢复。
5. 校验：`python cli.py --root <root> call hub_health`；GUI 打开确认记录/记忆条数正常。
6. 回滚：停写 → 把 `brain.db.before-restore-*` 改回 `brain.db` → 重启。

## 4. 任务管控：看板、租约、依赖与追溯

多 agent 共用同一块看板，四件事必须可判定：谁在干、是否还活着、这单卡在哪、接手后旧进程还能不能写。

### 4.1 看板与流转

- **看板**：`hub_tasks`（可按 status/project/owner 过滤）与 `hub_next`（前沿队列：可认领/进行中/可接管/等待）。每行行尾自动标注：截止紧迫度（已逾期/今天/临近）、前置进度 `n/m`、不存在的前置 `⚠前置不存在 #id`、残留阻塞、租约状态、进展停滞。
- **流转**：`hub_task_update(task_id, status=…, blocked_by=…, priority=…, deps=…, due=…)`。让任务从阻塞恢复时传 `blocked_by="-"`；重排截止日传 `due="YYYY-MM-DD"`，取消截止传 `due="-"`——**只有显式传 `-` 才清空**，缺省不动该字段（避免「改状态顺手抹掉截止日」）。看板上 `blocked` 状态却无阻塞原因的残留标记会标注「可清除」。
- **认领**：`hub_claim(task_id, agent)` 单条原子抢单；同一 owner 再次认领=续租，不重复写开工锚点。

### 4.2 租约与自愈

- 默认 2 小时（`brain.CLAIM_TTL_HOURS`）。心跳、`hub_task_update`、`hub_checkpoint` 都会续租。
- 超过 2h 未续租可被他人接管；**无主（无 owner）或缺失租约的在办任务也可以被 `hub_claim` 接管**（自愈），不再永久卡死。
- **撞车**：`hub_heartbeat` 会列出同项目他人持有的在办任务（含租约是否过期）。

### 4.3 依赖图（DAG）

- `deps` 用逗号分隔任务编号；前置未全部完成时任务不进前沿、不可认领。
- 自依赖与成环会被直接拒收，错误文案给出完整环路径（`#a → #b → #a`）；允许引用尚未创建的未来任务 id（正向规划）。
- 前置 id 写错或指向不存在的任务时，等待段显示「前置不存在 #id」；`tasks_health` 会连同自环、缺失前置一起点名。

### 4.4 检查点围栏与迟到写入

`hub_checkpoint(action="save", task_id, content)`：在办任务只收持有者的写入——非持有者拒收且不落行；写入成功同事务续租。任务被接管后，旧持有者因条件更新 `rowcount=0` 被拒，不会污染新持有者的进展时间线——这道写入围栏正是「租约决定谁能干、围栏决定迟到写入无效」的分工。

**进展停滞（R26）**：租约/心跳只证明持有者在线，不证明任务在走。推进口径是独立列 `progress_at`（认领/流转/改详情/写检查点会写，**心跳不碰**）加最新手工检查点；超过 `TASK_PROGRESS_STALL_HOURS`（默认 6h，= 3×租约 TTL）无推进即「进展停滞」。看板/控制面/GUI 显示 `⚠进展停滞 Nh`，`tasks_health` 单独计数；停滞与「持有者失联」互斥（先判失联），**只点名不自动释放**。修法：写 `hub_checkpoint(action="save")` 记录真实进展，或由持有者 `hub_task_update` 流转/更新后继续。

**时间口径（R27）**：四个钟各管一件事，谁都不能冒充谁——**推进**（任务级，`progress_at` 加手工检查点，只有真实任务动作会写）、**检查点**（任务级断点，认领锚点不算）、**心跳**（agent 级存活，取持有者最近一次 `sessions.ts`，不代表任务在走）、**租约**（还能不能被接管）。`tasks.updated` 会被心跳续租刷新，因此历史里只作「最后改动」展示；它与推进不一致时，时间线会另列一条「最后推进」。`hub_history(kind=task)` 头部给出一行四钟时刻，`hub_agent status` 的持有摘要列出推进/检查点/心跳（标注 agent 级）；`hub_list_agents` 只保留推进以维持单行密度。

### 4.5 文件租约（防「不同任务改同一个文件」）

任务租约只解决「谁干这单」，解决不了「两个人各干各的单、却同时改同一个文件」。`hub_lock` 是**建议性（advisory）**占位：不拦截文件写入，只让冲突在动手前可见——不阻断编辑器/脚本，也就不会误伤。

```text
hub_lock action=check   path=src/core.py                    # 只读查占用
hub_lock action=acquire path=src/core.py agent=zcode task_id=12 reason="改租约重入"
hub_lock action=renew   lease_id=7 agent=zcode ttl_min=60   # 或 action=acquire 同路径同主
hub_lock action=release lease_id=7 agent=zcode              # 或 path=... 释放自己在该路径的全部租约
hub_lock action=prune   limit=200                           # 回收过期未释放（只标记释放，活跃不碰）
hub_lock action=list    project=AgentHub-多agent文件统一管理
```

- **冲突口径**：同路径、以及祖先-子孙目录（锁 `src/` 与锁 `src/a.py` 互斥）都算冲突；相对根/绝对路径/`~` 均可，比较时统一 `normcase` + 正斜杠，Windows 大小写不敏感。
- **TTL** 默认 30 分钟（1~480 封顶）。过期租约可被他人接管，接管时该路径 `fence` 单调 +1——迟到写入可用它自证「我拿的是旧票」。
- **任务绑定**：传 `task_id` 时要求任务在办且持有者是调用者。任务完成/退回/换主/被接管会**自动释放**任务名下全部租约；绑定租约随心跳自动续，**未绑定租约不自动续**（防止忘了释放造成死锁）。
- **预警**：心跳列出同项目、其他 agent 持有的文件租约（含剩余分钟/任务/理由）；`hub_tasks`/`hub_next` 行尾显示 `锁 N`。
- **审计**：获取/续租/释放/任务级释放均写入 journal，`hub_history(kind="task")` 可见同一任务的全部占位轨迹。
- **巡检**：`hub_ops_run(name="lease_health")` 点名活跃冲突、任务绑定漂移（任务已完成/换主却没释放）、持有者未登记；过期未释放只报数供清理（它不拦人，不算失败）。
- **回收**：过期未释放用 `hub_lock action=prune`（或 `cli.py locks --prune`）一键回收——只标记 `released_by='expiry'`、记录保留（fence 仍是迟到写入的对照凭据），活跃租约永不触碰，重复调用幂等。
- **headless**：`python cli.py locks [--project X] [--owner A] [--path P]` 看台账/查占，`cli.py lock <path> --agent A [--task-id N]` 获取，`cli.py unlock <id> --agent A` 或 `unlock --path P --agent A` 释放，`cli.py locks --prune --agent A` 回收过期。

### 4.6 控制面与追溯

- `hub_agent(action="status", agent=…)` 与 `hub_list_agents` 显示每人持有的在办任务及租约状态；无主在办任务单列，提示可接管。控制面默认给「推进 Nh 前」，`hub_agent status` 额外列出检查点与心跳（标注 agent 级）。
- `hub_history(kind="task", id=任务编号)`：合并 journal 流转、检查点时间线、任务卡关键时点（创建/认领/完成），复盘「这单一路上怎么变成现在这样」。头部「时间口径」一行给出推进/检查点/心跳/租约四个时点，「最后改动」不等于进展。
- `hub_ops_run(name="tasks_health")`：过期租约/无主/持有者失联/进展停滞/逾期/依赖结构异常一次点名，只报不动手。
- 桌面「大脑」页任务看板对租约过期、进展停滞、逾期任务打徽标。

### 4.7 headless（CLI）

```bash
python cli.py --root <root> tasks --status in_progress      # 看板
python cli.py --root <root> next --agent zcode              # 前沿队列
python cli.py --root <root> claim 12 --agent zcode          # 认领/续租
python cli.py --root <root> update 12 --status done --agent zcode
python cli.py --root <root> update 12 --blocked-by -        # 清除阻塞
python cli.py --root <root> checkpoint 12 "完成第一批" --agent zcode
python cli.py --root <root> locks --project AgentHub-多agent文件统一管理
python cli.py --root <root> lock src/core.py --agent zcode --task-id 12
python cli.py --root <root> unlock --path src/core.py --agent zcode
python cli.py --root <root> locks --prune --agent zcode
python cli.py --root <root> call hub_history kind=task id=12
```

CLI 与 MCP 共用同一状态机、依赖闸门和持有者围栏；失败时退出码非零并打印具体原因。

## 5. 检索质量回归

```bash
python tools/eval_search.py                     # 当前库：MRR / Hit@1/3/5 / weak / 耗时
python tools/eval_search.py --records           # 记录侧
python tools/eval_search.py --root <冻结语料根>  # A/B 同一语料（防跨天数据漂移冒充回归）
```

输出会打印语料规模（memories / records 条数），**报告指标时必须带上规模**。冻结语料做法：用 sqlite backup API 把 `_hub/brain.db` 复制到临时根的 `_hub/` 下。评测 `count_hits=False`，不污染唤起统计。

## 6. 发布与桌面 exe

```bash
build.bat                        # 构建前 build-manifest start，打包后 finish + 复制桌面 + release 自检
python cli.py release            # 单独复查：产物 sha256 / 构建后源码哈希 / 桌面副本 sha256
```

- 桌面副本：`%USERPROFILE%\Desktop\AgentHub.exe`
- 构建清单：`build_manifest.json`（源码 md5 + exe sha256）
- `release` 三处任一不一致即失败；无清单时回退 mtime 并明示可能误报
- onefile 启动需解压，首次启动慢属正常；已排除文本嵌入用不到的视觉栈
- `deploy` 先全量复制到暂存目录并逐文件校验，成功后整目录原子换入；复制中断时旧部署原样保留（不会出现半新半旧模块）

改完源码后：先 `python cli.py deploy` 让 MCP 面生效，再 `build.bat` 让桌面 exe 生效。**其他 agent 的 MCP 进程需重启**，否则仍跑旧代码。

## 8. 错误分类与重试

工具失败时看 `structuredContent.error_kind`：

- `transient`：限流/库锁/资源忙 → 退避后重试
- `permanent`：参数非法/目标不存在/越权/键冲突 → 立即失败，别重试
- `ambiguous`：超时/结果未知 → **不要盲重试**；写工具用 `idem_key` 幂等键重放

写工具支持 `dry_run=true` 预演；`confirm=false` 返回 `input_required`（不阻塞服务端）。

## 9. 调用归属与使用观测

`hub_usage_timeline(view="stats", days=7)` 的「归属覆盖」行回答「控制面数据里有多少调用能追到人」：

- **有主**：`--agent` 进程锁定（最可信）> 写工具显式 `agent`（中）> initialize `clientInfo`（低，仅补已注册客户端）。
- **空**：客户端既没锁 `--agent`、也没自报可识别的 clientInfo。空归属高通常说明该 agent 的 MCP 配置缺 `--agent`，或仍在跑升级前的旧进程。
- **历史空行不回溯**：归属在调用发生时就已落库，事后无法可靠推断；修好配置并重启客户端后，新调用才会带主。

排查顺序：① `python cli.py status` 看该 agent 的 MCP 启动参数是否含 `--agent <注册名>`；② 重启客户端使新配置生效；③ 再跑 stats 确认「空」停止增长。筛选类工具（`hub_agent`/`hub_tasks`/`hub_usage_timeline`）的 `agent` 参数是「查谁」，不会被当作调用者。
